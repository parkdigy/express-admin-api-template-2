# Express Template 오케스트레이터

## 언제 사용하는가

- API, DB, 런타임 중 두 계층 이상의 계약이 함께 바뀌는 작업
- 요청 단위 트랜잭션, 서버 수명주기, 스케줄러 또는 배포 경계를 검토하는 작업
- 단일 계층의 단순 수정이나 테스트 보강에는 사용하지 않는다.

## 필요한 입력

- 목표와 완료 기준, 변경 대상 계층, 외부 서비스·배포 허용 범위. 빠진 정보는 현재 코드와 요청에서 확인한다.

## 절차

1. 작업 전 Git 상태와 인접 구현을 확인하고 관련 참조 문서에서 변경 계약을 정리한다.
2. 필요한 경우 스키마·타입 → 쿼리 → 컨트롤러 → 라우트 순으로 계약과 export를 맞춘다.
3. 인증·미들웨어 순서, 트랜잭션 범위, 비동기 완료와 외부 부작용을 검토한다.
4. 관련 테스트 후 `npm run verify`를 실행한다. 번들·별칭·진입점 변경이면 산출물 영향을 확인하고 `npm run build:rspack`도 실행한다.
5. 실패한 검증과 실행되지 않은 후속 단계, 라이브 의존성 미검증 영역을 구분해 보고한다.

## 참조 선택

- 라우트·인증·컨트롤러·DB 작업에는 [API와 DB 계약](references/api-db.md)을 읽는다.
- 앱 초기화·전역·스케줄러·배포 작업에는 [런타임과 운영 경계](references/runtime-ops.md)를 읽는다.
- 두 영역이 관련되면 두 문서를 모두 읽는다.

## 산출물

- 구현: 계약이 동기화된 소스·테스트와 검증 결과
- 분석: 원인, 근거 경로, 영향 범위와 확인 방법
